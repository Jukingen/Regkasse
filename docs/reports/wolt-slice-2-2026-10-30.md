Kitchen status on `/orders/online` writes Wolt order status as a synchronous side effect. No new table and no new buttons.

## Migration

`20261030125427_AddWoltSelfDeliveryToOnlineOrderIntegrations`

Adds nullable `wolt_self_delivery` (`boolean`, no default) on existing `online_order_integrations`. No other table changes.

Intake stores `delivery.self_delivery` when the Wolt order document includes it. When the column is still null at `ready → completed`, one `GET {OrderBaseUrl}/v2/orders/{id}` resolves it. `true` stores true and sends `PUT .../delivered`. `false` or a missing field stores false, skips that PUT, and still writes local `completed`.

## Behavior

`OnlineOrderStatusService.UpdateStatusAsync` calls `WoltOrderStatusSync` before the local status changes.

| Local transition | Wolt |
|---|---|
| `pending → accepted` | `PUT {OrderBaseUrl}/orders/{id}/accept` |
| `accepted → preparing` | no call |
| `preparing → ready` | `PUT {OrderBaseUrl}/orders/{id}/ready` |
| `ready → completed` and `wolt_self_delivery=true` | `PUT {OrderBaseUrl}/orders/{id}/delivered` |
| `ready → completed` and false or missing | local `completed` only |

The bearer token comes from `IWoltAccessTokenSource.GetAccessTokenAsync(tenantId, externalLocationId)`.

HTTP 409 whose follow-up `GET /v2/orders/{id}` shows the target status (`PRODUCTION`, `READY`, or `DELIVERED`) counts as success and advances the local order once. HTTP 409 or 422 in any other state does not advance the order, sets `last_error`, and does not change `status`, `attempt_count`, or `next_attempt_at`, so the intake retry worker does not pick the row up for this failure.

`PATCH /api/admin/online-orders/{id}/status` still requires only `digital.orders.manage`. Super Admin passes through `system.critical`. A non-gastronomy tenant gets HTTP 403 `PROFILE_ENDPOINT_DISABLED` and no PUT on a Wolt call (`accept`, `ready`, or a delivered-time fetch). Website order transitions are unchanged. A known courier order (`wolt_self_delivery=false`) still completes locally.

The order DTO field `marketplaceStatusActionsEnabled` is false only when the order is linked to Wolt and the provider row is disabled or that venue has no active OAuth token. The existing status buttons, including cancel, stay hidden in that case.
